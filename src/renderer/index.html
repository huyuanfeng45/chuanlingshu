飞书配置

使用企业自建应用的 App ID 和 App Secret，长连接监听机器人消息。

项目

每个项目对应一个工作目录、一个 Codex 线程和一个飞书会话。

推荐绑定方式

  1. 在飞书新建一个群，把这个自建机器人拉进群。
  2. 复制你要接管的 Codex 会话 ID，直接发到这个群里。
  3. 传令书收到后会把当前飞书群绑定到对应 Codex 项目；之后群里的消息会进入这个 Codex 会话。

Codex 会话 ID 是什么

它是 Codex 线程 ID，格式类似 019f0000-0000-7000-8000-000000000000，也可以是 codex://threads/019f... 这种链接。

最稳的复制方式：打开左侧「Codex 线程」，点击「查询」，在结果里找到目标线程，复制 id、threadId 或 sessionId 的值。也可以在 Codex 里复制线程链接，把 codex://threads/ 后面的那段 ID 发到飞书群。

群里回复是否需要 @

默认情况下，飞书群里要 @ 机器人，机器人才能收到消息。想免 @ 接收群内所有消息，需要到飞书开放平台后台给自建应用申请并开通权限：获取群组中所有消息，权限 scope 是 im:message.group_msg。这是敏感权限，通常需要管理员配置和审核。

手动绑定什么时候用

如果要手动添加项目、指定 Codex 会话 ID，或已经知道飞书群的 chat_id，可以点开下面的手动绑定。飞书群 chat_id 一般是 oc_ 开头；不知道时，在群里发送 /whoami，日志或回复里会显示当前群的 chat_id。

先填飞书应用凭证

打开飞书开放平台，进入企业自建应用的「凭证与基础信息」，复制 App ID 和 App Secret 到这里。

找不到位置？ 开放平台后台 → 选择应用 → 凭证与基础信息 → 复制 App ID / App Secret。

建立机器人并启用能力

在飞书开放平台创建企业自建应用后，给应用添加「机器人」能力，并把机器人发布到企业内可用。

创建应用 选择「企业自建应用」，名称建议用「传令书」或你的团队名称。
添加机器人 进入应用能力，添加「机器人」能力，保存头像和描述。
发布版本 权限、事件和机器人能力配置完后，创建版本并发布到企业。
建议 先把基础机器人跑通，再配置免艾特；这样出问题时更容易定位。

设置免艾特触发词

群里不想每次 @ 机器人时，推荐设置触发词。传令书会只处理这些词开头的消息，避免群聊普通消息全部进入 Codex。

群里这样发： 传令书 帮我看一下这个项目为什么启动失败
真正完全免艾特 需要在飞书后台开通「获取群组中所有消息」，权限 scope 是 im:message.group_msg。这个权限较敏感，通常需要管理员审核。

添加权限与事件订阅

这一步决定机器人能不能收消息、发卡片、接收按钮点击，以及下载你发到群里的图片或文件。

把机器人拉进群并测试

最后在飞书建一个群，把机器人拉进去，然后用群消息完成项目绑定和测试。

查看群 ID在群里发送 /whoami，传令书会返回当前 chat_id。
绑定 Codex 线程复制 Codex 线程 ID，直接发到群里；或到「项目管理」手动填 Chat ID 和线程 ID。
开始桥接回到总览点击「启动桥接」，再从飞书发一条测试消息。
还建议配置 如果多人会在群里操作 Codex，可以在「飞书配置」里填允许的 Sender ID，避免陌生人触发任务。
